# ADR-0007: M3 扩展范围——检索+度量两方向，工时用手动录入

Status: accepted

M2 收尾后用户提出向主流项目管理工具（Linear/Jira/Trello）学习扩展功能，经 grilling 决策树
逐轮收敛。决定 M3 只做**检索**与**度量**两个方向，**效率方向全部砍掉**，工时采用**手动录入**
而非自动推导。本 ADR 记录范围取舍与被拒绝的替代方案，避免未来重复评估或误以为遗漏。

## 决策

1. **范围**：全局搜索（FTS5，标题/描述/评论，命令面板式）、保存视图（项目/标签/列维度，
   存浏览器本地）、项目模板（仅预设初始列名）、任务模板（预设标题/描述/标签）、周期时间
   （从 activity 的 task.moved 推导，dashboard 项目平均 + 任务详情单任务耗时）、工时（手动
   按日明细录入，新表）、WIP 限制（列上限 + 软警告）、CSV 导出。
2. **效率方向整体砍掉**：快捷键、批量操作、自然语言建任务、**自动化规则**都不做。理由是
   "列移动本身就是状态表达"——任务移到末列即完成，无需规则再附加动作。与 ADR-0003 原候选
   中的 Workflow Rule 撤销。
3. **工时 = 手动录入**（time_entry 表，按日明细），**不做自动耗时**。这是经反复权衡后的最终
   决定：起初倾向自动推导（从 task.moved 算列停留时间），但自动推导依赖"哪个列算进行中"
   的识别口径，而列名是用户自定义的；固定列模板会牺牲看板自由度，用户配置起始列又增加维护
   负担。最终选择手动录入，**列名/状态识别问题整体搁置**。
4. **不做回收站**：维持现有硬删除 + 删除确认弹窗，不做软删除改造。主流工具普遍有回收站，
   此为有意偏离，因单用户误删风险低。
5. **不引入 AI**：自然语言建任务用规则解析（关键字/日期/标签）即可，不依赖 LLM，保持单
   二进制、零外部依赖的定位。

## Considered Options

- **周期时间与工时**：周期时间（自动推导，流程指标）与手动工时（人力投入记录）语义不同，
  两者并存而非二选一。
- **固定列模板（待办/进行中/评审/完成）**：可让自动耗时口径简单，但牺牲自定义列自由，且
  已有项目需迁移，被拒绝；以"列位置语义"（首列=待办、末列=完成、中间=进行中）作为口径。

## Consequences

- 数据模型新增：time_entry 表（工时）、WIP 上限字段（column）、保存视图存 localStorage
  （无后端表）、模板无新表（前端预设即可）、FTS5 虚拟表（搜索，需与任务/评论写操作同步索引）。
- 搜索索引同步需接入 ADR-0006 的 dispatch 单出口（任务/评论写操作处补 FTS5 维护），避免
  索引与数据漂移。
- ADR-0003 的后置候选更新为：通知、MCP/AI、公开分享（自动化 Workflow Rule 已撤销）。
