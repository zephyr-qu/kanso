# ADR-0008: M4 扩展——新维度功能集（时间/价值/入口/收纳）

Status: accepted

M3 清单（ADR-0007）确认后用户提出质疑：已选功能仍属"看板增删的周边强化"，缺少主流工具
（Todoist/Linear/Jira）真正的新能力。经 grilling 重新评估，决定新增 **M4 阶段**引入
四个新维度，M3 清单保持不变（分阶段推进）。

## 决策

1. **时间管理**：截止日期（Due Date 字段 + 看板徽章 + dashboard 临期）、日历视图（按截止
   日期展示、拖拽改期）。**不做重复任务**。
2. **价值与关系**：优先级（Urgent/High/Med/Low 四档，替代"紧急"标签 hack）。**不做任务
   依赖、不做子任务/清单**（流程复杂度与单用户价值不匹配）。
3. **节奏与入口**：快速捕获（全局快捷键 + 悬浮按钮弹出快速添加框）、里程碑（项目内独立
   实体，名称+日期，任务可关联，dashboard 显示进度）。**不做收件箱（Inbox）项目**——快速
   捕获直接落项目，避免多一个概念。
4. **收纳与并行**：任务归档（隐藏保留、可取消归档、不参与 dashboard 统计但可被全局搜索
   命中）、泳道（按标签横向分组）。**不做项目归档**（项目已支持整体删除，隐藏需求低）。

## Considered Options

- **泳道分组维度**：按标签分组（已有数据、零新字段）优于按优先级分组（依赖优先级字段
  先行）与可配置（多一层设置）。
- **快速捕获入口**：全局快捷键 + 悬浮按钮优于集成进搜索命令面板（藏得深）与收件箱项目
  （多概念）。
- **里程碑形态**：独立实体 + 任务关联（表达力强、dashboard 可聚合）优于特殊标签（表达弱）
  与固定列（灵活性低）。
- **归档行为**：任务归档且可搜索（信息不丢失）优于"归档全隔离"（冷数据难找回）。与
  ADR-0007"不做回收站/保持硬删除"不冲突——归档是隐藏保留，删除是永久移除。

## Consequences

- M4 数据模型新增：task 表加 due_date、priority、archived_at 字段；milestone 新表 +
  task_milestone 关联；日历视图纯前端（复用任务查询）；泳道纯前端（按标签分组渲染）。
- 归档任务仍被 FTS5 搜索命中，但被看板/统计查询过滤——需在查询层统一过滤口径
  （`archived_at IS NULL`）。
- 截止日期与周期时间/工时互不干扰：due_date 是计划时间，周期时间是流程时间，工时是投入记录。
- M4 与 M3 可部分并行（如优先级、截止日期字段可与 M3 的看板/搜索同时排期），里程碑/泳道
  依赖 M3 的标签体系稳定后落地。
